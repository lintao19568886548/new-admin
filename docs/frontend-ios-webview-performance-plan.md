# iOS 与微信 WebView 首屏性能专项方案

## 1. 目标

苹果用户和微信内置浏览器用户数量较多，本专项把 iOS Safari、iOS 微信 WebView、低网速移动网络作为优先优化对象。目标不是让所有后台资源一次性加载更快，而是让用户先看到可恢复、可操作的界面，避免白屏和无限转圈。

## 2. 当前判断

项目已经具备部分基础能力：

1. 业务路由大量使用动态导入。
2. 动态 import 已有重试封装。
3. 全局已有 `window.error`、`unhandledrejection`、Vue errorHandler 兜底。
4. 构建层已把 `echarts`、`exceljs`、`jspdf`、`univer`、`vxe-table` 等重依赖单独拆包并移出初始预加载。
5. 启动 loading 已有慢加载提示。

真正剩余的核心问题是：登录页虽然是动态路由，但 Vue 启动壳在登录前仍会提前加载全局样式、Ant Design、Ionic、Capacitor、store、i18n、插件、路由和布局等框架级资源。iOS 对大 JS 下载后的解析和执行更敏感，所以同样的包体在 PC 或部分安卓上正常，在 iPhone 上可能长时间转圈。

## 3. iOS 高风险场景

| 场景 | 表现 | 处理 |
| --- | --- | --- |
| JS 解析慢 | 资源下载完成但页面仍卡在启动 loading | 登录前启动壳瘦身，减少初始 JS 执行 |
| 旧缓存混用 | 发布后点击菜单白屏或 chunk 加载失败 | chunk 失败自动重试，失败后刷新并绕过旧 HTML 缓存 |
| iOS 微信 WebView | Safari 正常，微信里慢或报模块加载失败 | 单独识别 WebView，缩短慢加载提示时间 |
| 弱网/断网 | loading 长时间不消失 | 启动页显示网络慢/离线提示和重新加载入口 |
| 初始预加载太多 | 登录前抢占网络下载后台资源 | 继续过滤非首屏重依赖的 modulepreload |

## 4. 第一阶段开发范围

第一阶段先解决“白屏无限转圈”和“旧缓存失败无法恢复”：

1. 启动 loading 识别 iOS、微信 WebView、离线、慢连接。
2. iOS/慢连接更早显示提示和重新加载按钮。
3. 重新加载使用 cache-bust 查询参数，降低旧 HTML 缓存命中。
4. 接入 Vite `vite:preloadError` 事件，捕获 modulepreload 和动态 chunk 失败。
5. 资源失败自动刷新最多一次，避免无限刷新。
6. 文档化 iOS 真机验收标准。

## 5. 第二阶段开发范围

第二阶段做真正的启动壳瘦身：

1. 登录前不初始化后台布局、菜单、业务 store、图表、复杂插件。
2. 把后台布局和业务插件移动到登录成功之后加载。
3. 对 Capacitor、Ionic、VueQuery、Motion、微信 JSSDK 等非登录必需能力做延迟初始化。
4. 构建后检查登录链路 chunk，确保不包含图表、导出、打印、富文本等重依赖。

## 6. 第三阶段开发范围

第三阶段优化后台首页和页面切换：

1. 首页统计、图表、字典接口分批加载。
2. 移动端默认先展示核心列表或入口，非核心卡片延后加载。
3. 页面级接口超时展示重试区域，而不是只弹 toast。
4. 菜单切换保留当前可见内容，局部 loading，不整页白屏。

## 7. 缓存和发布要求

1. `index.html` 必须 `no-cache, no-store, must-revalidate`。
2. 带 hash 的 JS/CSS 可以长缓存。
3. 发布新版本时保留旧 hash 资源一段时间，避免旧页面还在引用旧 chunk。
4. 不要让 CDN 对 HTML 做长缓存。
5. 如果未来启用 Service Worker，必须单独设计更新策略；当前项目没有主动注册 Service Worker。

## 8. iOS 验收矩阵

必须覆盖：

1. iPhone Safari。
2. iPhone 微信内置浏览器。
3. iPhone App WebView。
4. 弱网环境：Slow 3G 或真实低信号 4G。
5. 发布后旧页面点击菜单触发 chunk 加载。

通过标准：

1. iPhone 上启动超过数秒时出现明确提示和重新加载按钮。
2. 资源失败最多自动刷新一次，不无限刷新。
3. 自动刷新后仍失败时展示可操作错误页。
4. 未登录访问后台地址时，不长时间停在空白 loading。
5. 登录后后台内容可以渐进加载，不能整页无反馈。

## 9. 执行顺序

1. 先完成启动页、资源失败、旧缓存兜底。
2. 再做登录前启动壳瘦身。
3. 再做后台首页和高频页面的渐进加载。
4. 最后用 iPhone 真机和微信 WebView 做回归。
