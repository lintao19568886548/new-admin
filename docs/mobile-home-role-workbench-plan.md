# 移动端首页角色化工作台开发文档

## 目标

把移动端 `首页` 从固定的 `考勤/报销/访客` 三块，改成按当前登录用户角色展示的个人工作台。

首页原则：

- `考勤打卡` 固定保留，作为第一优先入口。
- 下方展示用户当前最重要的待办和常用模块。
- 不同角色看到不同内容，不再所有人都固定看到 `报销申请`、`访客管理`。
- 未登录时允许看首页壳和通用入口，但点击业务功能统一提示：`想要使用完整的功能，请先进行登录`。

## 页面结构

移动端首页分三段：

1. `考勤打卡`
   - 原 `今日打卡` 改名为 `考勤打卡`。
   - 展示上班打卡、下班打卡、当前签到状态。
   - 点击后进入考勤打卡页面。

2. `我的待办`
   - 展示当前角色最需要处理的事项。
   - 每个待办包含：图标、标题、数量/状态、简短说明、跳转入口。
   - 数量暂时复用现有接口能拿到的数据；没有成熟统计接口的模块先展示快捷入口，不强行造假数据。

3. `重要模块`
   - 展示当前角色最常用的功能入口。
   - 每个入口点击后进入对应移动端页面。
   - 登录后按实际权限显示；未登录展示通用预览入口。

## 角色识别

优先使用现有用户信息：

- `userStore.userRoles`
- `userStore.userInfo`
- `userStore.userInfo.reimbursementAuth`

角色判断采用“能力优先”而不是只看角色名：

- `Super`：超级管理员/老板视角。
- `reimbursementAuth > 0`：有报销审核能力，展示财务/报销审核待办。
- 命中人事相关角色名或菜单能力：展示人事、考勤、请假、人员信息。
- 命中招商相关角色名或菜单能力：展示招商工作台、客户登记、公开需求、公开房源。
- 命中门禁/前台相关角色名或菜单能力：展示访客、车辆出入、门禁管理。
- 命中维护相关角色名或菜单能力：展示报修、变压器、电梯、消防、厂房维护。
- 无法识别时：展示通用工作台入口。

后续如果后台角色命名不统一，前端可以通过“菜单是否存在”辅助判断。

## 路由跳转

- 已登录：进入目标页面。
- 未登录：提示 `想要使用完整的功能，请先进行登录`，跳转 `/auth/login?redirect=目标路径`。

## 数据接口策略

第一版以“可稳定落地”为目标：

- 考勤打卡：沿用 `getTodayRecord`。
- 报销统计：沿用 `getReimbursementSummary`。
- 访客动态：沿用 `getVisitorList`，只取最近 3 条。
- 其他模块如果没有现成轻量统计接口，先显示快捷入口和待处理占位文案，不做重接口聚合。

后续可补充专用聚合接口：

- `/api/mobile/home/summary`
- 后端按用户角色一次性返回首页待办、数量和模块入口。
- 避免前端首页同时请求多个业务接口。

## UI 要求

- 手机端优先，避免 PC 卡片风格。
- 不在卡片里再套复杂卡片。
- 信息密度适中，首页首屏至少能看到 `考勤打卡` 和一部分 `我的待办`。
- 待办卡片用清晰数字、短描述、明确入口。
- 重要模块采用 4 列图标宫格。
- 不展示“没有权限”文案。

## 验收标准

- 未登录进入移动端首页，不强制登录。
- 未登录点击任意业务入口，提示 `想要使用完整的功能，请先进行登录`。
- 登录后能回到点击前目标页面。
- `今日打卡` 已改为 `考勤打卡`。
- 财务/报销审核角色能优先看到报销审核。
- 超级管理员能看到更综合的管理入口。
- 门禁、招商、人事、维护角色能看到各自重要模块。
- ESLint 通过。
- `pnpm -F @vben/playground typecheck` 通过。
